# Contributor photo permissions

Migration 026 adds an author-only consent projection and revision-fenced publication changes. It follows 022. The guest HTTP path requires the current contribution cookie, exact expectedGuestId and exact submission author. Receipt routes cannot read this contributor projection or grant publication permission.

The projection returns actual submission, gallery and wall grant booleans, the individual grant revision and the current receipt. Publication moderation states are not used to infer consent. The mutation changes only gallery and wall permission; private delivery remains enabled. Existing whole-photo withdrawal stays on the reduction-only legacy path.

The event, submission and grant are locked before reading or updating. A current revision may change permission; an immediately repeated revision with exactly matching current booleans returns current state without another write. Any later revision rejects stale increases, including an old grant after a withdrawal. The renamed 022 body preserves renewed-consent awaiting-approval behaviour. Its service grant is removed. The legacy unfenced RPC permits reductions only, closing a bypass through old clients. No request receipt table or unbounded retry history is added. At saturated integer revision, increases stop while reductions and whole-photo withdrawal remain possible.

Paused and closed events allow changes to already accepted submissions until their existing access/retention expires. No expiry is extended. Private guestbook text and its withdrawal are independent of gallery and wall permissions.

The optional ownConsentVersion capability defaults to zero on older deployments. The standalone EventGuestConsentPanel loads server values explicitly, freezes an unconfirmed update, requires confirmation before discarding it, aborts on hidden/unmount and clears the surface on lost authority. It is wired to accepted guest records through the capability-gated Photo permissions action. The parent photo and guestbook controls are inert while editing. The rehearsal adds Lose next permission response and Withdraw permissions elsewhere for exact-retry and stale-restoration checks. Reservation recovery retains its original consent fingerprint after later permission edits.
