# Private memory previews and annual exports

`lib/memories/memory-media.ts` accepts existing account-fenced `RetainedStripClient` and `CloudProjectClient` instances belonging to the same owner. It exports `assertMemorySource`, `prepareMemoryThumbnail` and `renderAnnualMemoryRecap`. The preview/export methods return a PNG Blob and dimensions. They never create object URLs, start downloads, save a cloud derivative or persist signed links. The UI owns display lifetime and must recheck selected sources again on its explicit Download action.

A strip requires a fresh private retained resolver, verified download and final resolver check. A project original requires a fresh accepted project view containing that exact photo, a fresh source read, its integrity-checked download, then another view/read and exact metadata comparison before publication. Deleted, expired, hidden, concealed or unavailable originals are errors, never silently substituted. A previously displayed activity row is not source-read authority. An explicit image reference or decoration does not become a captured-photo activity.

The pipeline processes one original at a time. Before native decoding it checks still-image headers and the exact expected dimensions/MIME: retained PNG at most 16 MiB, project JPEG/PNG/static WebP at most 10 MiB, each at most 4096 pixels per edge and 12 Mi pixels. Each decoded original is immediately reduced to a canvas no larger than 640 pixels per edge, then its bitmap is closed. An annual selection holds at most twelve such thumbnails and one output canvas. The shared annual recap compositor preserves aspect ratios and uses the actual maximum thumbnail width and height as cell dimensions, without upscaling. Its largest unscaled twelve-item output is 2740 × 2394; narrow strips and smaller originals produce a more compact canvas. All outputs are bounded to 4096 pixels per edge and 12 Mi pixels. Encoded previews are at most 2 MiB and annual PNGs at most 32 MiB.

One module-wide native allocation slot covers previews and annual exports, including injected test instances. Overlap fails with `busy`. Each native decode/encode has a ten-second caller deadline, and the operation has a two-minute deadline. Abort or timeout rejects the caller promptly, but the slot and any canvas involved in pending `toBlob` remain held until the underlying native operation settles. Late bitmaps are closed and late Blobs discarded. This does not claim native cancellation; a browser operation that never settles keeps the slot unavailable until page reload. Navigation/account changes must abort the caller signal and release any UI-owned preview URL.

No capture time is invented: annual labels and title are explicit caller inputs, usually from the memory view's civil timezone. The existing weekly recap branch and its callers are preserved.

`tests/memory-media.test.ts` verifies source denial/change, sequential download order, cleanup after a later failure, real PNG header reduction, stale account rejection, selection/output geometry bounds and native late-completion ownership through injected decode/canvas ports. Browser decoding, pixel appearance and downloaded-file behaviour require the native UI rehearsal; the Node tests alone do not prove those behaviours.
