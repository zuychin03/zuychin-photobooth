# Private project object adapter

`lib/server/project-objects.ts` is a source-level server adapter. It does not enable cloud projects, add routes or run a worker. Deployment remains disabled until the existing feature and database gates are satisfied. No hosted requests were made for this implementation.

`createProjectObjects({ origin, serviceRoleKey }, { fetch?, now? })` accepts a trusted configured service origin, HTTPS or loopback HTTP, and a server-only key. Callers must first obtain fresh authority from the project store or a current leased job. A structurally valid descriptor is not proof of membership, consent or a live lease. Do not expose this factory or its descriptors as a body-forwarding client API.

The four methods are:

- `mintUpload(ProjectUploadAuthorisation)` returns `{ signedUrl, token, path }`. It checks the exact bucket and three-UUID path, bounded bytes, `overwrite=false`, mint window and recorded upload/cleanup deadlines. The mint deadline is checked immediately before dispatch and again after the complete provider response. A late result is rejected. No `x-upsert` header is sent, matching the installed SDK's `upsert:false` behaviour. The bucket ceiling still applies to tokens; a smaller declared size is not a provider-enforced upload limit.
- `download({ bucket, path, bytes? })` returns a bounded `Uint8Array`. It reads only the authenticated original endpoint. Optional `bytes` is the exact expected length and a tighter streaming ceiling. Otherwise the ceiling is 10 MiB. Content-Length is checked before reading and against the final body; chunked responses cannot bypass the cap. Empty images, malformed lengths and excessive chunks fail. MIME, SHA-256 and actual decoding remain the finaliser's responsibility.
- `signRead(ProjectAssetAccess)` returns `{ signedUrl }` with the existing 300-second lifetime, without transformations or alternate representations. Resolve current access immediately before this call, without caching descriptors. Existing tokens and downloaded copies cannot be recalled by revocation.
- `removeAndConfirmAbsent({ bucket, path })` deletes only that exact original and then makes an authenticated HEAD request for the same path. Only HTTP 404 returns true. HTTP 200 returns false; 400, denied access, rate limits, provider errors, redirects and uncertain transport results throw. The leased SQL completion step must still verify its lease and absent metadata before releasing capacity.

Each provider request, including its streamed body, has a 10-second deadline. Deletion and its subsequent absence check are two sequential requests. Redirects are rejected; the final response URL must exactly match the configured request URL. Signed URLs must match the configured origin and exact expected endpoint, with exactly one nonempty bounded token and no credentials, fragment or other query fields. JSON bodies are capped at 64 KiB. Stalled readers are cancelled on timeout; a transport ignoring abort cannot publish a late response. Raw provider errors, response bodies, keys and token URLs are never included in adapter errors or logs.

Provider routes and response fields were inspected in installed `@supabase/storage-js` 2.110.2, `src/packages/StorageFileApi.ts`: `createSignedUploadUrl`, `createSignedUrl`, `download`, `remove` and `exists`. Direct fetch preserves those REST contracts while avoiding unbounded SDK Blob reads and its treatment of both 400 and 404 as an existence failure. The actual hosted Storage service, signed-token enforcement and provider response behaviour remain activation checks.

`tests/project-objects.test.ts` uses injected Response streams and a fake clock. It covers exact request authority, invalid origins/paths, upload expiry before and after minting, signed URL substitution, bounded streamed bytes, redirects, sanitised errors, deletion/absence statuses, stalled bodies and late responses. These are local adapter tests, not hosted Storage evidence.
