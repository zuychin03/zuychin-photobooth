# Server image finalisation primitive

`lib/server/image-finalise.ts` is a server-only byte primitive. It performs no fetch, token mint, upload, database assertion or worker activation. Inputs are bounded `Uint8Array` values, never paths or URLs. Sharp 0.35.4 is an exact direct dependency; its Apache-2.0 licence is included in the installed package. The local runtime uses libvips 8.18.6.

`verifyProjectOriginal(bytes, expected, options)` snapshots the input, verifies JPEG/PNG/static-WebP structure and actual native pixel decoding, and compares oriented dimensions, MIME, byte count and SHA-256 with the reserved metadata. It returns the unchanged original separately from verified metadata. Original EXIF/ICC data is intentionally preserved in that private original; it must not be confused with a sanitised public derivative. Decoration originals additionally require PNG, at most 4 MiB and 2048 pixels per edge.

`finaliseEventImage(bytes, options)` accepts at most 2,000,000 input bytes and produces a JPEG image of at most 2,000,000 bytes plus a JPEG thumbnail of at most 100,000 bytes. Output MIME, dimensions, bytes and SHA-256 describe the actual encoded output. Sequential quality/edge reductions meet the byte budgets or fail explicitly. The thumbnail starts at a 400-pixel edge; neither output enlarges a smaller source. Aspect ratio is preserved, EXIF orientation is applied, colour is converted to sRGB, metadata is omitted and transparency is flattened onto white. A future finalisation worker must store these outputs under its current fenced lease before committing ready metadata.

Both operations reject input over 4096 pixels per edge or 12 MiPixels before native decoding. PNG CRCs, critical chunks, ordering and termination are checked; JPEG marker structure and exact end-of-image are checked; WebP RIFF size, known chunks, padding and static flags are checked. Native decoding with `failOn: "warning"` and `limitInputPixels` remains mandatory. Header inspection alone never establishes `decoded: true`. SVG, GIF, APNG and animated WebP are outside this contract.

Only one primitive job runs per process; another request fails with `image_busy` rather than joining an unbounded queue. One oriented RGBA buffer is retained at a time, at most 48 MiB at the pixel bound, plus bounded input/output buffers and Sharp/libvips working memory. This is not a hard process RSS limit. The primitive does not alter global Sharp cache/concurrency settings used by Next.js. A deployed worker still needs a process memory limit and bounded scheduling across instances.

The caller deadline defaults to ten seconds and accepts 1–10,000 ms. Cancellation and deadline expiry reject the caller, but do not claim to kill native work. The occupied slot remains held until the real native promise settles; late decoded buffers are cleared and no result is returned. Sharp's cooperative timeout also runs, but its documented timer excludes time waiting for a libuv thread. Worker/container termination is the external escalation for a stuck decoder. No new job is admitted merely because a timeout response was returned.

The current adapter APIs are suitable for future 002 project and 005 event workers. They do not authorise an actor, resolve concealed content, validate an event lease, establish contributor consent or prove durable Storage writes. Those checks remain mandatory around invocation. Failed verification must retain existing quota reservations until confirmed cleanup; it must never cause a client-supplied `decoded` assertion to be trusted.

`tests/image-finalise.test.ts` generates actual PNG/JPEG/progressive JPEG/static and animated WebP fixtures. It checks independent output decoding, orientation, preserved hashes, metadata removal, transparent matte, byte budgets, malformed containers, valid headers with absent compressed pixels, caller mutation and aborted native work followed by retry. These local codec checks do not exercise a hosted worker or provider lifecycle.
