# Event guest uploads and receipt delivery

This source tranche extends the existing cookie-authorised event routes. `PB_EVENTS_ENABLED` remains false. No hosted migration, provider token, object upload or account operation was performed. Event transport/schema readiness, the configured public origin, trusted IP header and service credentials remain prerequisites. Successful capability responses advertise the implemented upload and receipt-download methods; that is not evidence of provider activation.

`POST /api/events/<event>/guest` accepts `upload` with `submissionId` and `expectedGuestId`. Reserve, consent and finalise also require `expectedGuestId`, which must match the contribution session captured from the HttpOnly cookie. A cookie replaced by a different guest cannot mutate that guest's submission accidentally. Guest requests charge both IP and verified guest rate buckets. Receipt requests charge IP and exact receipt identity buckets. Neither identifier supplied by a browser creates authority.

Upload authorisation is persisted before signing. The response is `{submissionId,bucket,path,signedUrl,expiresAt,maxBytes,overwrite:false}`. The only bucket is `photobooth-event-images-staging-v2`; the path is `<event>/<submission>/source`; `maxBytes` is 2,000,000. The browser uses PUT with no overwrite at the configured Storage origin's `/storage/v1/object/upload/sign/<bucket>/<path>?token=...`. The installed Storage SDK uses this PUT protocol and omits `x-upsert` when minting an immutable upload.

The adapter validates the provider response URL, exact object path, token presence and JWT expiry/scope claims. This checks the trusted provider's response; it does not authenticate caller-supplied JWTs. Both legacy unscoped provider tokens and explicit upload/download scopes are supported, with immutable `upsert:false` required for upload. The mint deadline is checked immediately before and after the request, and once more after the fresh session check. Issued expiry cannot exceed the persisted authorisation deadline or the two-hour native upload lifetime. An ambiguous mint retains the pessimistic staging reservation, even when no URL reaches the browser. [Supabase documents the two-hour signed-upload lifetime](https://supabase.com/docs/reference/javascript/file-buckets-createsigneduploadurl).

`POST /api/events/<event>/receipts/<submission>` accepts `media` with no additional fields. It requires the exact receipt cookie, ready submission, current contributor consent and the existing read gate. Receipt state and read permission are fetched again after signing. The response is `{submissionId,bucket,path,signedUrl,expiresAt,maxBytes,mime}` with `photobooth-events-v2`, `<event>/<submission>/image`, 2,000,000 and `image/jpeg`. It contains no other submission or contributor information. Gallery and display delivery are not added by this endpoint.

Read tokens are bounded by the original promised retention deadline and at most 300 seconds. Signing reserves ten seconds of provider latency, so a normal request asks for 290 seconds, and a request with ten seconds or less remaining is refused. Already issued links may remain usable until their expiry; revocation cannot recall downloaded copies. The current SQL read projection does not expose a verified output digest or dimensions. Consumers may bound and decode the JPEG but must not claim an independent immutable-hash check. Adding those fields requires a separately validated SQL projection.

Provider work uses the existing two-request process ceiling, ten-second abort, 64 KiB control-response cap, 4,096-chunk cap, redirect rejection and exact response-URL checks. A transport that ignores abort retains its request slot until it actually settles. Signed URLs and tokens remain ephemeral, never durable recovery journal fields or log values. HTTP replies are private, no-store and no-referrer.

Local evidence on 23/09/2026: 27 focused tests passed across event object, request and signing suites. Cases include exact paths and no-overwrite protocol, excessive expiry/foreign URL/malformed claims, pre/post mint expiry, retention headroom, replaced guest identity, cancellation, and revocation during receipt signing. The tests use synthetic provider responses and real route/store validation. Hosted JWT formats, bucket enforcement, Storage trigger rollback semantics and real provider clocks remain activation checks. The earlier disposable PostgreSQL plus actual Sharp worker evidence is recorded in [P7_EVENT_IMAGE_WORKER.md](P7_EVENT_IMAGE_WORKER.md).
