# Event publication contract

Migration022 extends the approved E3 gallery, wall and moderation scope. It remains a source artefact, with no hosted migration, provider call or enabled flag. `PB_EVENTS_ENABLED` remains the existing default-off gate. `publicationVersion:1` is independent of P7 capabilities and019 worker readiness. No kiosk or remote-postcard permission is introduced here.

## Authority and routes

POST `/api/events/{id}/gallery` and `/wall` accept separate gallery and display capabilities. Neither a contribution cookie, receipt, account nor moderator membership substitutes for an audience token. The owner issues these existing token kinds through016;017 revokes them. Explicit `exchange {token}` returns a public session UUID and writes one bounded HttpOnly cookie per surface. Production uses `__Host-pb-event-gallery` / `__Host-pb-event-display`, Secure, SameSite=Strict and Path=/; local development omits Secure and scopes the cookie to `/api/events`. Cookies last at most30 days and never beyond the authorised event/token expiry. No raw token or hash enters projections or reports.

`capabilities` returns the exact shared limits; `session` validates current authority. Every subsequent operation requires `expectedSessionId`, preventing a late tab from silently adopting a replacement cookie. `list {after?,limit?}` returns at most12 UUID-ordered approved entries. `validate {submissionIds}` checks at most12 displayed IDs independently of pagination. Responses include server `checkedAt` and minimum event/token expiry, with no source-project IDs or guest identity. Public event UUIDs are routing identifiers, never authority.

`access` / `media {submissionId,variant}` authorise an exact immutable delivery object. Wall allows only thumbnails; gallery may explicitly request the full image. Thumbnail bounds are100,000 bytes and400px per edge. Full images are at most2,000,000 bytes,4096px per edge and12MP, with hash and dimensions from the verified finaliser checkpoint. Thumbnail hashes/dimensions are unknown rather than invented. The provider signer runs between two fresh SQL access checks; changed revision, descriptor, token or consent suppresses the returned link. Existing signed URLs expire within five minutes and cannot recall a prior download.

All routes require same-origin JSON, HTTPS except development loopback, strict bounded bodies, finite deadlines and durable rate checks. Audience routes require the configured trusted IP header outside local development. Responses are private/no-store/no-referrer. GET returns a private denial and never exchanges credentials. No Storage listing is exposed. Browser token-fragment removal, rendering and freshness enforcement are separate client work.

## Publication and privacy

Each submission has a monotonic publication revision, changed by delivery/publication transitions and consent changes. Approval requires ready verified bytes, unanimous current submission and destination consent, accepted owner/moderator authority and the exact current revision. Consent withdrawal makes only that surface private; renewed unanimous consent returns it to awaiting approval. It never restores a prior approval. Hide/reject affects only its selected destination. Underlying submission withdrawal/removal and contributor revocation deny every future event read, preserving physical-cleanup accounting.

POST `/api/events/{id}/moderation` uses verified Supabase actor authority. Operations are `capabilities`, `list`, `decide`, `remove`, `reports`, `report`, `resolve`. List returns current states, revision and unanimous-consent booleans. `decide {submissionId,destination,expectedRevision,state,requestId?}` requires an immutable request UUID only for approval. The event has at most512 approval receipts; exact replay returns the current entry without reapplying an old approval. Hide/reject use current revision without allocating a receipt, and `remove` is idempotent once deleted. Capacity exhaustion never prevents these privacy actions. Clients reconcile their latest entry after a lost response.

Legacy service `pb_event_manage(...,'publication',...)` now rejects with `PB_EVENT_UPDATE_REQUIRED`; its underlying renamed function is not executable by service clients. Other P7 actions and finalisers continue through their existing entrypoints. Internal helpers and tables are not directly granted to anon, authenticated or service roles. Forward-migration reruns preserve populated state.

## Reports and freshness

Audience reports require currently visible content; an accepted owner/moderator may report privately reviewable content. Reports contain an immutable request UUID, one of privacy/inappropriate/other, and at most500 text characters. There is one report per reporter/submission/surface and at most100 reports per event. Reporters are domain-separated hashes only. Retrying an existing report succeeds after moderation hides the item; changing its payload conflicts. Reports do not automatically hide or publish anything. Host/moderator report lists are paginated, omit reporter hashes, and expose one-way idempotent resolution. The existing bounded event maintenance sweep deletes report details/hashes for at most25 expired/deleted events per pass, at the next successful maintenance invocation.

The client must poll every5 seconds and discard displayed media no later than10 seconds after the start of its last successful authorisation request. Validation errors, offline/hidden state, identity changes and expiry clear URLs immediately. This application freshness deadline is distinct from provider signed-link expiry. Retain at most12 gallery thumbnails or3 wall images; no private Cache Storage or persistent signed URLs. Actual browser and hosted cache/revocation behaviour require separate evidence.

It uses the actual TypeScript store, service grants, locks and concurrent connections. Cases cover all four publication choices with two contributors, stale approval after re-consent, withdrawal racing approval, distinct token/session authority, wall-original denial, approval replay, concurrent last report slot, saturated privacy actions, current private receipt preservation,019-stale reads, direct helper/table denial and empty/populated migration reruns. Storage objects and provider proofs are synthetic metadata, not hosted Storage evidence.

Focused handler/parser tests cover disabled gates, forged authority/origin, duplicate and wrong cookie kinds, changed session, malformed payloads, strict response identity and mid-signing revocation/revision changes. Native audience rendering and real provider delivery remain separate checks.
