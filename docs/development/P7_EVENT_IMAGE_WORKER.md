# Event image maintenance

This tranche integrates the existing 005 event job protocol with the installed Sharp codec and a bounded Storage adapter. `GET /api/events/maintenance` requires `PB_EVENTS_ENABLED=true`, the configured service origin/key and exact `Authorization: Bearer <CRON_SECRET>`. Query credentials and non-GET requests are refused. Responses are private and no-store. The flag remains disabled; no hosted resources or scheduled invocation were configured.

The019 integration additionally checks independent worker schema support and renews readiness only after an acknowledged verified pass. Stale readiness never prevents bootstrap/recovery execution. Successful HTTP responses include `workerReady:true`; failed or uncertain work cannot renew the heartbeat. Finalisation now has claim priority over older cleanup jobs. The dedicated finite runner, admission ceiling and required cadence are documented in [P7_EVENT_WORKER_RUNBOOK.md](P7_EVENT_WORKER_RUNBOOK.md). The ordinary15-minute media scheduler does not run this worker.

Each pass checks the schema, sweeps at most 25 submissions and claims at most one job. The existing SQL uses an exclusive submission lease for 120 seconds and at most eight attempts. `checkpointJob` renews the exact token and rechecks finalisation deadlines, contributor consent and revocation before each external effect. Jobs cannot change identity, kind or token between checkpoints. An uncertain completion acknowledgement is retained rather than followed by a contradictory retry/failure assertion.

The three exact object locations are derived from trusted event/submission UUIDs. Staging uses `photobooth-event-images-staging-v2/<event>/<submission>/source`; delivery uses `photobooth-events-v2/<event>/<submission>/image` and `/thumbnail`. There is no caller-controlled URL, bucket or arbitrary path. Downloads stream at most 2,000,000 bytes for originals/images and 100,000 bytes for thumbnails, with a 4,096-chunk ceiling, declared-length checks and ten-second abort deadlines. Redirects and mismatched response URLs are rejected. Service credentials are never returned or included in errors.

`finaliseEventImage` performs structural validation and real native decoding of JPEG, PNG or static WebP. It checks oriented dimensions within 4,096 per edge and 12 MiPixels. One shared native slot covers project, retained-strip and event processing. A ten-second logical timeout or cancellation does not release that slot until Sharp actually settles. The largest decoded RGBA buffer is 48 MiB, plus bounded compressed input/output and native codec overhead; this is not a measured process-memory guarantee.

Event output is deterministic, metadata-stripped JPEG on a white matte, with the existing sequential quality/size ladder. Images stay at most 2,000,000 bytes and thumbnails at most 100,000 bytes. The original remains staged until its recorded upload-token cleanup deadline. No GIF, clip, audio, ZIP or new event media kind is introduced.

Writes are POST-only and explicitly `x-upsert:false`. Raw-byte upload headers follow the installed `@supabase/storage-js` implementation: JPEG content type, `cache-control:max-age=0`, and base64 JSON `x-metadata` containing `eventJobId` and `eventLease`. The existing SQL trigger expects those fields in `storage.objects.user_metadata`. Both output objects are fetched again and compared with the freshly encoded exact byte lengths and SHA-256 hashes before `decoded` and `objectsVerified` are checkpointed. Previously written identical derivatives are reused without overwrite. A missing readback remains retryable; mismatching immutable bytes fail finalisation and remain charged pending cleanup.

Cleanup confirms each exact object using successful deletion followed by strict HTTP 404. HTTP 400, 403, 500, a still-present object or an interrupted request never proves absence. Only after all required paths are confirmed absent does the worker checkpoint `deleted=true`. The final SQL transaction independently requires metadata absence and the staging expiry fence before releasing any charge or contribution slot. Failed cleanup retains its accounting and needs operator attention.

The route has a 90-second caller deadline and one active pass per handler instance. Late work retains that busy guard until it settles. Provider requests have a separate two-request process ceiling held until actual transport settlement, including an injected transport that ignores abort. Distributed workers still depend on SQL leases. The codec can logically time out while native work finishes in its separately held slot, preventing another decoder from accumulating behind it.

Local evidence uses actual Sharp, the actual EventStore adapter and a uniquely named disposable PostgreSQL database. The worker harness exercises service-role metadata insertion through the existing Storage trigger, finalisation checkpoints, exact derivative accounting, post-completion write denial and delayed staging cleanup. HTTP response bytes and the provider's mapping into Storage metadata are explicit fixtures. This does not prove hosted token behaviour, object-store rollback on rejected metadata writes, cross-service cancellation or physical orphan absence. Those remain activation gates; no claim of full P7 completion is made.

Commands: `npx tsx --test tests/event-objects.test.ts tests/event-maintenance.test.ts tests/image-finalise.test.ts` and `npx tsx database/tests/run-event-worker.mjs`. The latter is confined to the task-owned local PostgreSQL container and drops its own database in `finally`.
