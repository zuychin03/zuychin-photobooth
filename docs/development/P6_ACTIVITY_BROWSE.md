# Chronological memory browsing

The memory UI needs chronological pages within an explicitly chosen civil year. Forward migration 013 and the existing activity client/store/handler now add `browse(query)` without changing the older UUID list or UTC summary contract. This is a source foundation for the upcoming memory page, not a completed interface or hosted activation.

The exact query contains `year` (1970–2198), `timeZone` (IANA), `chapterId` (personal chapter or null for all), `after` (null or exact occurrence timestamp plus UUID) and `limit` (1–50). The server computes the two year-boundary instants with the existing calendar primitive. It uses the first valid local midnight, choosing the earlier occurrence if midnight repeats and shifting through a gap. The interval is half open. The SQL function independently bounds it to 364–367 elapsed days, accommodating civil-year offset changes and a skipped dateline day. It never accepts a browser actor or directly supplied time interval.

Rows sort by occurrence descending, then UUID descending. Cursor timestamps preserve PostgreSQL microseconds; millisecond Date comparisons cannot skip rows with distinct sub-millisecond timestamps. Both browser and server verify ordering, date bounds, exact filter echoes and the last-row cursor. Private chapter filtering requires that chapter's owner, and shared activity never acquires another member's private labels.

The new RPC reuses `pb_memory_projection` and `pb_memory_scope_visible`. Owners keep existing minimal lost-scope participation; removed and newly paired partners do not gain historical sources. The independent browse capability gates only this operation. Existing UTC summaries continue to mean own source-record totals in UTC; they cannot be relabelled as civil-year or available-photograph totals. Detailed activity is still subject to the existing bounded retention policy, and browsing does not recreate missing photographs.

Local evidence: five new tests plus existing activity/ritual request tests passed together (**33/33**). Coverage includes Sydney/Vietnam year boundaries, Samoa's 2011 skipped day, exact microsecond and UUID ordering, malformed filters, response drift, personal chapter projection, real client/handler/store integration and one rate charge. The disposable `run-memory-browse.mjs` SQL harness passed service-role-only execution, inclusive start/exclusive end, tied timestamp pagination without duplicates, private chapters, unpair/re-pair isolation, minimal lost-source records and populated reruns. Its uniquely named local database was removed afterwards. No hosted SQL or provider requests were made.
