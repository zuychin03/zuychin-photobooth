The lib/ directory is organized as a flat collection of single-purpose modules rather than a layered architecture: each file owns one concern (e.g. `camera.ts` for MediaStream access, `capture.ts` for frame extraction, `filters.ts` for CSS filters, `segmentation.ts` for MediaPipe cutouts, `cloudinary.ts` for uploads, `push-client.ts`/`push.ts` for web push, `auth.tsx`/`session.tsx`/`room-code.ts` for auth/session state). Cross-cutting concerns are split by environment — Supabase client usage lives in sibling files (`couple.ts`, `photo-dates.ts`, `retention.ts`, `streak.ts`) while real-time collaboration would use an `rtc/` package if present. Modules communicate through plain function exports and React context providers (`.tsx` files) rather than a central orchestrator; consumers import only what they need from this flat namespace.
